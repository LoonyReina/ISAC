## 2026-10-11 实际云浏览器检查

使用云端 Chromium；桌面 1173 CSS px（100%），窄屏 391 CSS px（300% 缩放，视口高度约 250 CSS px）。缩放导致可视高度较短，图形分段滚动检查，不称为物理手机测试。

通过的观察：

1. 桌面冷启动 `foundations.html#cfar` 正确定位章节；窄屏独立冷标签页中 CFAR 顶部为 150.135 CSS px，七步 OFDM 已增强且只显示第一步
2. 窄屏章节目录在深处保持可达，键盘可以展开，列表可内部滚动，链接使用原有章节锚点
3. OFDM 的键盘“下一步”显示第二步并将焦点放到 H3；旧 `#velocity-matching` 显示第七步；键盘“上一步”显示第六步并聚焦相应 H3
4. 实验目录中的双站检测标题实际点击到 `#question`；论文卡标题也指向该入门入口；明确的实验按钮保留 `#experiment`，四个先修分别显示实际学科主题
5. 双站检测 Pfa=0.999999999999、ρ=10⁻¹⁰ 时显示 `<100%` 与正的独立漏检率；391 CSS px 下两张概率图的文字包围盒不再相交，页面无横向溢出

真实浏览器额外发现两项需要修正的问题：

- 短视口中，活动章节原先使用 0.28×视口高（约 70 px）选取；实际锚点却落在根滚动留白的 150.135 px，导致检测章节入口仍高亮上一章。修正应同时考虑根 scroll-padding 和可见粘性标题的遮挡范围，不能只看视口比例
- 原生章节链接通过键盘激活时，事件处理器先聚焦 H2，但随后的浏览器默认锚点动作又把焦点移回 BODY。仅模拟点击回调不足以验证；需在默认动作后、有历史 / 哈希保护地恢复标题焦点

后续小修分别针对上述实际发现；数值核心不受影响。小修的本地回归不能替代发布后的再次浏览器验证。
