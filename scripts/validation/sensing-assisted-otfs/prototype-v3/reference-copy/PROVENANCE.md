# Oracle provenance and evidence boundaries

`reference.py` and `CONTRACT.md` are verbatim copies of the independently accepted, bounded Python reference. The reference is never edited or regenerated by these tests. Its required SHA-256 is `c83ba035ee49d8011c2b3b8f5f0260b7e95fd2fb562781f03e63a1ea7407ddce`.

`independent-audit/review_reference.py` and `independent-audit/audit_oracle.py` are verbatim copies of the accepted independent review sources. The former has a historical harness path which is deliberately not executed here. The generator extracts its `scalar_messages` function by Python AST without changing the function and supplies only NumPy and the independently authored coordinate/normalization functions. It does not import the implementation under test into the scalar oracle.

`../fixtures/independent-source-fixtures.json` is copied verbatim from the separately produced source audit. Its SHA-256 is `435bb73f5237389f12b47b26f622804daad03be805c05b5493739b837a3a1ace`.

The evidence layers are separate:

1. Full-output port parity compares all fields of JavaScript `sparseSpa` against pinned Python `sparse_spa`, including probability rows, known-pilot semantics, masks, decisions, status, iteration count, all history entries, and effective variance inputs.
2. An independently written scalar-loop message schedule checks probability vectors separately from the vectorized reference implementation. This tests the interpreted message equations and scheduling, not the exact physical posterior.
3. Independent direct-scatter observations, conditional covariance/pseudo-covariance/cross-covariance, finite factor mixtures, and exact tiny known/unknown-gain posteriors validate mathematical claims separately. The retained converged surrogate-to-exact discrepancy is approximately 0.499913, not a failed port assertion.

Fresh random fixtures use declared NumPy seeds and include all receiver input arrays and evaluator-only truth/noise arrays. The oracle receiver's extra physical gain/support information is labeled explicitly. Deliberately mismatched support is passed unchanged to practical receivers. Zero/weak-gain parameter probes are identified as probes instead of being described as ordinary pilot estimates.

The Node test additionally constructs a newly seeded observation at runtime, invokes the live JavaScript kernel, and exports raw inputs and complete outputs. Python independently reconstructs that observation and verifies the full output and separately authored scalar oracle. This is Node runtime evidence; browser execution and Worker lifecycle evidence require their own tests.

## Floating-point half ties

The source tiny fixture has symmetric, uninformative marginals whose values can fall on opposite sides of 0.5 by approximately 1e-16 in NumPy and JavaScript. The raw probability rows, hard decisions, and decision-change history remain unchanged. The verifier allows a different hard decision only if both implementations' positive marginals are within 3e-12 of 0.5. It independently reruns every iteration with `maxIterations=k, tolerance=0` and reconstructs both decision-change counts, proving that any count difference is entirely explained by current or previous such ties. All non-tie decisions, counts, statuses, and iteration counts must match exactly. Numerical fields retain their declared numerical tolerances. Raw discrepancies and complete rerun traces are saved in `../reports/oracle-tie-diagnostic.json`; this is an explicit cross-language rounding boundary rather than bit-for-bit categorical parity.

None of these checks proves a whole-paper reproduction, paper-sized curves, sensing-derived support prediction, guaranteed BER gain, exact posterior inference by Gaussian SPA, or a live deployment.
